TWO IMPLEMENTATIONS

Transparency vs. Scale

Built the same architecture twice, to feel the tradeoff between mathematical clarity and commercial speed with my own hands.

Pure Python

microgpt.py · shakespeare_gpt.py

A custom Value class wraps every scalar and dynamically builds a computation graph, calculating gradients via manual chain-rule backprop. No PyTorch, no NumPy — zero dependencies.

  • Full autograd engine written from scratch
  • ~4,192 parameters
  • Minutes to process a few Shakespeare batches
The Lesson: math is visible, speed is not.

PyTorch

shakespeare_pytorch.py

Same architecture, rebuilt on optimized C++/CUDA tensors. Scaled 50x in parameter count and trained in a fraction of the time — the same foundational design that powers GPT-2 and GPT-3.

  • Vectorized tensor operations
  • ~210,000 parameters (50x larger)
  • Learns capitalization, syntax, character names
The Lesson: tensors, not tricks, are the real speedup.

THE CORE IDEA

One class. The entire chain rule.

Every operation — add, multiply, power, ReLU — records its own local derivative. backward() walks the computation graph in reverse topological order, multiplying local gradients along the way. That's backpropagation: no magic, just the chain rule applied recursively.

def __add__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    return Value(self.data + other.data, (self, other), (1, 1))

def __mul__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    return Value(self.data * other.data, (self, other), (other.data, self.data))

def relu(self):

THE "AHA!" MOMENT

From Shakespeare bot to GPT-3

The PyTorch model here runs the exact same foundational architecture as GPT-2 and GPT-3. The only difference is scale and data.

01

Scale the tokenizer

Swap character-level tokenization for Byte-Pair Encoding (BPE) to process whole syllables and words.

02

Scale the data

Trade a 1MB file of Shakespeare for a 10TB scrape of the internet.

03

Scale the brain

n_layer 4→96, n_embd 64→12288. That's a 175-billion parameter model (plus a few million dollars in GPU compute).

04
